# Proof-to-Pipeline — The Replicable Protocol

The agent-runnable version of the P2P prompt: what an AI operator (or Claude itself,
as a skill) executes end-to-end. This file is the process documentation; the
shareable prompt is `../PROMPT_Proof-to-Pipeline.md`.

## Phase 0 · Recon (before any question)

1. Inventory reachable data sources (Drive, CRM, email platform, notes, repos).
   **Never plan around "files on my computer" until confirmed reachable** — cloud
   sessions cannot see local disks; promote laptop-only material to a synced source.
2. Map the client corpus: lists, deliverables, live instruments, brand assets,
   contracts, existing agents/skills.
3. Read the client agreement — confidentiality AND work-product/IP clauses — before
   promising any public-facing asset. Note the consent authority by name.

## Phase 1 · Interview (10 + up to 5)

One question at a time; four options each (three specific + one open/hybrid); refine
per answer. Sequence: strategy → content → assets → mechanics:
job-of-the-deliverable → positioning → confidentiality line → gift artifacts → brand
system → capture design → CRM landing → logistics/date → success metric. At Q10:
summarize, offer ≤5 extras, the human decides continue vs. build. Ground questions
in Phase-0 evidence; at contested forks, pull live pipeline data and let it argue.

## Phase 2 · Build

- **Deck**: minute-marked outline first, then the file, in the owner's brand system;
  client work shown in client branding. Aggregate numbers only. Build anonymized
  variants of client slides in parallel (consent insurance).
- **Promo**: one-pager in the same system.
- **Gift kit**: one prompt + one agent, sanitized to methodology (slots, not client
  data). Kit README carries the scheduler link.
- **Prep**: Q&A sheet weighted to the audience; day-by-day pre-talk checklist.

## Phase 3 · Capture

Form (minimum viable fields — one identity field, respondent's choice) → instant kit
email → single follow-up → CRM rows with `Lead source` provenance → bookings tracked
against a Floor/Target/Stretch scorecard.

## Phase 4 · Deliver

Present. Drop the capture link in chat at minute N-1. No pitch beyond one
availability line.

## Phase 5 · Retro (the loop)

Obtain the session transcript. Run a continuous-improvement pass:
- What landed (audible reactions, questions that showed engagement)
- What dragged (sections that ran long, restated slides)
- What was asked (Q&A themes → next version's content, new FAQ entries)
Revise deck, promo, Q&A sheet, and THIS protocol. Commit. The loop is the product.

## Reuse

For the next client/project: copy this directory, run the prompt with new slot
values, keep the protocol file — it accretes lessons across projects via Phase 5.
